GitHub Analytics

Analyzing the GitHub Network

Author

Farhan Sadeek

Published

August 12, 2026

Abstract

This project analyzes the GitHub social network from the MUSAE project. The network contains 37,700 developers and 289,003 undirected edges representing mutual follower relationships. Each developer is labeled as either a Machine Learning Engineer or a Web Developer. Graph analysis is used to study connectivity, hubs, degree distributions, centrality, communities, mixing patterns, random-graph comparisons, and small-world structure.

Introduction

Motivation and Importance

GitHub is one of the most important platforms for hosting and sharing open-source software. Developer profiles function as public portfolios, while follower relationships provide a useful lens for studying visibility, influence, and the organization of the software-development community.

Prior Work

The data are part of the MUSAE project, which introduced multi-scale attributed node embeddings for node-classification tasks. This analysis applies classical network methods to the same developer network.

Limitations

The data are a snapshot collected in June 2019 and therefore may not represent the current developer ecosystem. The binary job-title label omits many occupations, the network treats follower relationships as mutual, and the minimum-follower threshold of ten excludes less-visible developers.

Data

Source and Creation

The network was collected through the GitHub API as part of the MUSAE project and is distributed through the Stanford Network Analysis Project collection. Edge data are stored in musae_git_edges.csv; developer labels are stored in musae_git_target.csv.

Methods and Analysis

Top Hub Nodes

The most connected developers are predominantly labeled Web Developers. The largest hubs include dalinhuang99, nfultz, addyosmani, Bunlong, and gabrielpconceicao. These nodes illustrate the highly concentrated visibility structure of the network.

Vertex Centrality

Degree, betweenness, closeness, and eigenvector centrality reveal different forms of importance. Degree and eigenvector centrality identify highly connected and influential developers; betweenness identifies bridge-like nodes; closeness measures reachability through the network. Most measures are strongly correlated, while betweenness is comparatively distinct.

Figure 2. Correlation between centrality measures.

Component Structure

There is one connected component containing all 37,700 nodes and 289,003 edges. The graph has 350 articulation points, so a relatively small set of structurally important developers can determine whether peripheral regions remain connected.

Transitivity and Clustering

The global transitivity is approximately 0.0124, while mean local transitivity is approximately 0.1934. The gap suggests that local neighborhoods can contain triangles even though the network as a whole is dominated by hub-and-spoke connectivity.

Figure 3. Distribution of local clustering coefficients.

Community Detection and Graph Partitioning

Fast-greedy community detection identifies 335 communities with modularity 0.3957. The partition reveals a central connected structure surrounded by many smaller communities.

Figures 4-5. Graph partitioning and k-core size distribution.

Assortativity and Mixing Patterns

Degree assortativity is approximately -0.075, indicating mild disassortativity: high-degree hubs tend to connect to lower-degree peripheral developers. Job-type assortativity is approximately 0.378, indicating substantial homophily between Web Developers and Machine Learning Engineers.

The observed edge counts are 224,623 Web-Web edges, 44,696 Web-MLE edges, and 19,684 MLE-MLE edges. After accounting for the number of possible pairs, within-group edge probabilities remain higher than the cross-group probability, supporting genuine professional homophily rather than a simple group-size artifact.

Comparison with Random Graph Models

The observed network has mean degree 15.33, degree standard deviation 80.79, transitivity 0.0124, and average path length 3.24. An Erdős-Rényi graph with the same size and density has transitivity 0.0004 and average path length 4.14. A configuration model preserves the degree sequence and produces similar path length, while Watts-Strogatz and Barabási-Albert models highlight the roles of clustering and preferential attachment.

Small-World Assessment

Using the report’s comparison with the Erdős-Rényi baseline, the clustering ratio is approximately 30.2 and the path-length ratio is approximately 0.78. The resulting small-world score is

\[\sigma = \frac{C_{obs}/C_{ER}}{L_{obs}/L_{ER}} \approx \frac{30.2}{0.78} \approx 38.7.\]

Because \(\sigma \gg 1\), the network exhibits small-world structure: developers are separated by only a few intermediaries, while local neighborhoods are substantially more clustered than a comparable random graph.

Results

The network is a simple, sparse, globally connected graph with a highly skewed degree distribution. A small elite of hubs dominates connectivity. The network also shows small-world behavior, mild negative degree assortativity, and strong professional homophily.

Discussion

The network’s articulation points and high-degree hubs create potential gatekeepers. Removing important hubs could fragment otherwise global connectivity. Professional homophily may also produce echo chambers in which developers preferentially connect to others with similar job types. The observed structure is broadly consistent with preferential attachment and the accumulation of attention by established developers.

Future Work

Future analysis should use newer data, especially given the rapid growth of machine learning and generative AI. Link prediction could model how the community grows, while exponential random graph models could test higher-order structural mechanisms. More complete job and activity attributes would also provide a richer representation of developer identity and interaction.
