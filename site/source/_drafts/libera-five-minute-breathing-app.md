Libera walks you through a five-minute session of breathing, mindfulness, guided visualization and a short journal entry. Alex and I built it at Hack Dartmouth X, in one weekend in April 2026, as a Next.js web app, and I ported it to Flutter on the last morning. The thing I'd keep from it is a small design choice. **A breathing exercise is four numbers (inhale, hold, exhale, hold), and once the app treats it that way, the animation, the on-screen cue and the mobile port all fall out of the same data.** The background sound works the same way. Rain, brown noise, a cello drone and a singing bowl are generated by about 130 lines of Web Audio code, so the app ships with no sound files at all.

It is a hackathon build. It has one shared session flow, three practice packages, a free-access library and an insights page, and two people built it between Saturday evening and Sunday noon.

## Why It Matters

Most breathing apps either give you a timer and a circle or bury a short exercise under a subscription and a content library. We wanted something in between. It would be a short, structured session you could finish between two classes, with a sense of progress across weeks, and it wouldn't need you to pick from a menu every time.

So a Libera session is always the same five steps.

| Step | Length |
|---|---|
| Mood check-in (emoji slider) | 10 s |
| Breathwork | 80 s |
| Breath watching | 80 s |
| EFT visualization (guided imagery) | 90 s |
| Micro-journal (three prompts) | 60 s |

That adds up to 320 seconds, a little over five minutes. What changes is the package. "The Morning You Love" uses cyclic sighing, "The Earned Moment" uses box breathing, and "The Lighter You" uses slow diaphragmatic breathing, and each package has its own guided visualization script and its own last journal question. A 30-level path cycles through the three packages in order, so the app decides what today's session is and you just start it.

## Technical Details

### A Breath Pattern Is Data

Every breathing technique in the app reduces to the same record. Box breathing is 4 seconds in, 4 held, 4 out, 4 held, repeated 5 times. Cyclic sighing is 4 in, 6 out, 2 held, 7 times. Diaphragmatic breathing is 4 in, 7 out, 2 held, 6 times. Those are the only parameters, and they live in one type.

```ts
export interface BreathPattern {
  name: string;
  inhale: number;   // seconds
  holdIn: number;
  exhale: number;
  holdOut: number;
  cycles: number;
}
```

Everything on screen during the breathwork step is a function of that record and the elapsed time. The cycle length is the sum of the four phases. The position in the current cycle is the elapsed time modulo that length. The phase label is whichever interval that position falls in, and the circle's size is a keyframe animation whose keyframe times are the same phase boundaries divided by the cycle length. Each pattern's cycles also land close to the 80-second step (80, 84 and 78 seconds), so the circle finishes roughly where the timer does.

### Sound From Oscillators

The ambient menu has four tracks, and none of them is a recording. Each one is a small graph of Web Audio nodes built when you press play.

- **Rain** is pink noise (white noise run through a bank of leaky integrators, the Voss-McCartney approximation) passed through an 800 Hz high-pass filter, which leaves the hiss of drops and removes the rumble.
- **White noise** is actually brown noise. Each sample is a small step away from the last one, which piles the energy into low frequencies, and a 500 Hz low-pass softens it further.
- **Cello** is three sawtooth oscillators on C3, G3 and C4, each with its own slow vibrato and a low-pass filter to take the buzz off.
- **Singing bowl** is four pairs of sine waves, each pair detuned by 1.5 Hz so the two tones beat against each other the way a real bowl's partials do.

Noise buffers are four seconds long and loop. Changing track closes the whole audio context and builds a new one, which is the simplest way to make sure nothing from the old graph keeps playing.

## Implementation

### The Web App

The web app is Next.js with the App Router, Tailwind and Framer Motion, with Supabase for accounts and row-level security. I wrote the session flow, which covers the five-step modal, the package definitions, the 30-level path, the mood slider with a smiley thumb, the visible countdowns and the ambient audio menu.

The breathing circle is where the "pattern as data" idea pays off. The text label updates once per second from the countdown, but the motion is a separate Framer Motion keyframe animation, so the circle moves smoothly between ticks. The keyframes come straight from the pattern.

```ts
const scaleValues: number[] = [1, 1.5];
const timeValues: number[] = [0, inhale / cycleLen];
if (holdIn > 0) {
  scaleValues.push(1.5);
  timeValues.push((inhale + holdIn) / cycleLen);
}
scaleValues.push(1);
timeValues.push((inhale + holdIn + exhale) / cycleLen);
if (holdOut > 0) {
  scaleValues.push(1);
  timeValues.push(1);
}
```

A hold phase is just two equal keyframes. Adding a new technique to the app means adding one record. Nobody has to touch the animation code.

The sound code follows the same approach of building it from parts. Here is the singing bowl.

```ts
frequencies.forEach((freq, i) => {
  const osc1 = ctx.createOscillator();
  osc1.type = 'sine';
  osc1.frequency.value = freq;

  const osc2 = ctx.createOscillator();
  osc2.type = 'sine';
  osc2.frequency.value = freq + 1.5; // slight detune → beat frequency

  const lfo = ctx.createOscillator();
  lfo.frequency.value = 0.1 + i * 0.05;
  // ... LFO into the pair's gain, pair into the master gain
});
```

A 1.5 Hz detune gives a slow pulse, and the slow LFO on each partial's volume makes the higher partials swell and fade at different rates, so the drone never sounds exactly periodic.

### Alex's Half

Alex built most of what happens after the breathing. He wrote the EFT visualization step and expanded the guided scripts, built the insights dashboard (mood over time, a vividness score for how clearly you could picture the visualization, a session timeline and streaks), added narration for the scripts, and built the Open Exercises library, which has five breathing patterns, four guided meditations, four EFT scenarios and a habit-breaker widget, all usable without the path.

Narration goes through a single `useTTS` hook. It tries a hosted voice first and falls back to the browser's own speech synthesis at a slower rate of 0.88, so the scripts still get read aloud on a machine with no server-side voice configured.

### The Flutter Port

I ported the app to Flutter on Sunday morning, about 3,700 lines of Dart across screens and widgets, with `provider` for state and `go_router` for navigation. The port went quickly because the hard part was already data. The session steps, the three packages and the library carried over as Dart classes nearly field for field, and the breathing circle became a `TweenSequence` whose segment weights are the phase lengths.

```dart
if (p.inhale > 0) {
  items.add(TweenSequenceItem(
    tween: Tween(begin: 0.4, end: 1.0)
        .chain(CurveTween(curve: Curves.easeOutQuart)),
    weight: p.inhale.toDouble(),
  ));
}
if (p.holdIn > 0) {
  items.add(TweenSequenceItem(tween: ConstantTween(1.0), weight: p.holdIn.toDouble()));
}
```

Framer Motion takes keyframe times as fractions of the cycle, and Flutter takes segment weights that it normalizes itself. Underneath, they're the same four numbers.

I also built the presentation as a route inside the app, so the demo and the slides ran from one deploy.

## Problems

### 1. A Smooth Circle on a One-Second Clock

The session runs on a countdown that ticks once per second, and my first version computed the circle's scale from that tick, so a four-second inhale moved in four steps. Alex fixed it. **The fix was to stop driving motion from the timer at all.** The timer only decides which phase label to show. The circle gets its own repeating keyframe animation with the cycle length as its duration, so the browser interpolates every frame, and the two stay in sync because they share a start time and a period.

### 2. The Presentation Route Disappeared

The slides lived at `/presentation`, but the app's root layout wrapped every page in the sidebar, top bar and bottom nav, so the deck rendered inside the app shell and looked broken. **Next.js route groups solved it without moving any URLs.** The app pages went under `(main)` with the shell layout, and the deck went under `(presentation)` with a bare layout.

## What I Would Change

The audio is the part I'd keep and extend. Synthesized tracks cost nothing to ship and can react to the session, so the next step is to tie them to the breath, for example lowering the filter cutoff during the exhale or swelling the bowl on each inhale. I'd also share the session data between the web app and the Flutter app from a single JSON file rather than keeping two hand-written copies, since that data is the part both apps actually agree on.
